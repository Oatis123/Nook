# ТЗ: Self-hosted «заметки + задачи» (рабочее название — **Nook**)

> Документ для AI-агента, который реализует проект с нуля.
> Язык ТЗ — русский. **Язык интерфейса приложения и Telegram-бота — только английский.**
> Название «Nook» — рабочее, вынеси его в одну константу/переменную окружения, чтобы легко заменить.

---

## 0. Правила работы для агента

1. Реализуй всё, что описано в разделах 1–15. Не упрощай функционал молча. Если что-то невозможно или противоречиво — остановись и задай вопрос.
2. Где в ТЗ написано «на усмотрение агента» — выбери решение сам и зафиксируй его в `docs/DECISIONS.md` (одна строка: решение + причина).
3. Следуй порядку этапов из раздела 14. После каждого этапа проект должен собираться, запускаться через `docker compose up` и проходить тесты.
4. Пиши тесты одновременно с кодом, а не в конце. Логику напоминаний и изоляцию данных пользователей покрывай тестами обязательно.
5. Дизайн — отдельный приоритет (раздел 10). Интерфейс не должен выглядеть как типовой сгенерированный ИИ шаблон.
6. Никаких секретов в коде. Все настройки — через `.env`, с примером в `.env.example`.

## 1. Обзор продукта

Веб-приложение для self-host, объединяющее:

- **Notes** — аналог Obsidian в браузере: markdown-заметки в папках, теги, `[[wikilinks]]`, бэклинки, граф связей, полнотекстовый поиск, вложения, импорт/экспорт Obsidian vault.
- **Tasks** — таск-менеджер в духе TickTick: списки/проекты, приоритеты, подзадачи, повторяющиеся задачи, виды List / Today / Upcoming / Calendar.
- **Telegram-бот** — напоминания о задачах и создание задач из чата.

Пользователи: владелец сервера (админ) + несколько приглашённых людей. **Данные каждого пользователя полностью изолированы**, совместной работы нет.

## 2. Технологический стек

### Backend
- Python 3.12+
- FastAPI, Pydantic v2
- SQLAlchemy 2.x (async) + asyncpg, миграции — Alembic
- PostgreSQL 16 (полнотекстовый поиск через `tsvector` + `pg_trgm` для нечёткого поиска по названиям)
- aiogram 3 — Telegram-бот
- `python-dateutil` (RRULE для повторяющихся задач), `zoneinfo` для часовых поясов
- `dateparser` — разбор дат из текста (английский обязательно, русский желательно — для бота)
- argon2 (`argon2-cffi`) — хеширование паролей
- Отдельный процесс-воркер для напоминаний (без Redis/Celery — см. раздел 8.4)
- Инструменты: `uv` или `poetry`, `ruff`, `mypy`, `pytest`, `pytest-asyncio`, `freezegun`/`time-machine`

### Frontend
- React 18+ + TypeScript + Vite
- React Router, TanStack Query (серверное состояние), Zustand (локальное UI-состояние)
- **CodeMirror 6** — markdown-редактор
- `unified` / `remark` / `rehype` (remark-gfm, собственный плагин для wikilinks и embeds, rehype-sanitize), подсветка кода — `shiki`
- Граф: `d3-force` + canvas, либо `sigma.js`/`react-force-graph` — на усмотрение агента, главное — производительность от 2000 узлов
- Календарь: собственная реализация на `date-fns` (предпочтительно) или FullCalendar с **полной** перестилизацией под дизайн-систему
- Разбор дат в quick add: `chrono-node`
- Стили: Tailwind CSS поверх собственных дизайн-токенов (CSS-переменные). Доступные примитивы — Radix UI (unstyled)
- Иконки: Lucide, stroke 1.5, размер 16px
- Шрифты подключаются локально через `@fontsource` (без Google Fonts CDN)
- Инструменты: ESLint, Prettier, Vitest, Playwright (e2e)

### Инфраструктура
- Docker Compose: `db`, `api`, `worker`, `bot`, `web` (nginx: статика фронта + reverse proxy на `/api`)
- Опционально: пример конфига Caddy для HTTPS в `docs/`

## 4. Пользователи, роли, доступ

- Роли: `admin`, `user`.
- Первый админ создаётся командой `docker compose exec api python cli.py create-admin` (интерактивно) **или** из переменных `ADMIN_USERNAME` / `ADMIN_PASSWORD` при первом старте, если в БД нет ни одного пользователя.
- **Изоляция данных:** у каждой пользовательской сущности есть `user_id`. Любой запрос к данным фильтруется по текущему пользователю на уровне сервисного слоя (общий хелпер/репозиторий, а не ручные фильтры в каждом роутере). Доступ к чужому объекту по id возвращает `404`, а не `403`.
- Админ **не видит** заметки и задачи других пользователей — только управляет аккаунтами.

### Админ-панель (`/admin`)
- Создание инвайта: срок жизни (по умолчанию 7 дней), необязательный комментарий. Результат — одноразовая ссылка.
- Список инвайтов: активные / использованные / истёкшие, отзыв инвайта.
- Список пользователей: username, роль, статус привязки Telegram, дата регистрации, последний вход.
- Действия: деактивировать/активировать, сбросить пароль (генерирует одноразовую ссылку сброса), отвязать Telegram, назначить/снять роль admin (нельзя снять с последнего админа).

## 5. Авторизация и онбординг

### 5.1 Регистрация (только по инвайту)
1. Пользователь открывает ссылку инвайта `/invite/<token>`.
2. Задаёт username (уникальный, `a-z0-9_`, 3–32 символа) и пароль (минимум 10 символов).
3. Часовой пояс определяется из браузера и сохраняется (можно поменять позже).
4. **Обязательный шаг — привязка Telegram** (5.2). Пока Telegram не привязан, приложение показывает только экран онбординга (gate). Это касается и админа.

Открытой регистрации нет.

### 5.2 Привязка Telegram (deep link, работает без публичного домена)
1. Бэкенд создаёт одноразовый токен привязки (TTL 10 минут).
2. Фронт показывает кнопку **Connect Telegram** → `https://t.me/<bot_username>?start=link_<token>` и QR-код с этой ссылкой.
3. Бот получает `/start link_<token>`, проверяет токен, сохраняет `telegram_user_id` и `chat_id` у пользователя, отвечает приветствием.
4. Фронт опрашивает статус (polling каждые 2 с или SSE) и после успеха пускает в приложение.
5. Один Telegram-аккаунт может быть привязан только к одному пользователю.

### 5.3 Вход
- **Username + пароль.**
- **Log in with Telegram** (для уже привязанных): фронт получает токен входа → пользователь открывает `t.me/<bot>?start=login_<token>` → бот присылает сообщение с кнопками **Confirm login** / **Deny** и информацией об устройстве/IP → после подтверждения фронт получает сессию.
- Опционально (если задан `PUBLIC_DOMAIN` и настроен домен в BotFather) — Telegram Login Widget. По умолчанию выключено.

### 5.4 Сессии и безопасность
- Access JWT (15 минут) + refresh token (30 дней, хранится в БД в хешированном виде, ротация при каждом обновлении).
- Оба — в `httpOnly`, `Secure`, `SameSite=Lax` cookies. CSRF-защита через double-submit token для изменяющих запросов.
- Rate limit: логин — 5 попыток / 15 минут на username+IP.
- В настройках: смена пароля, список активных сессий, выход со всех устройств, отвязка/перепривязка Telegram.

## 6. Модуль Notes

### 6.1 Папки и заметки
- Дерево папок с неограниченной вложенностью в левом сайдбаре.
- Создание, переименование, перемещение (drag & drop) папок и заметок; сортировка по имени / дате изменения.
- Удаление — в **корзину** (soft delete), автоочистка через 30 дней, восстановление, очистка вручную.
- Имя заметки уникально в пределах папки.
- Заметка хранит: `title`, `content` (markdown), `folder_id`, `version`, даты создания/изменения. Поддерживается YAML frontmatter (`tags`, `aliases`).

### 6.2 Редактор
- **Split view:** слева markdown (CodeMirror 6), справа превью.
- Превью **можно включать/выключать** (кнопка в тулбаре + хоткей `Ctrl/Cmd+E`). Состояние запоминается в настройках пользователя.
- Синхронная прокрутка редактора и превью (можно отключить).
- Подсветка markdown-синтаксиса, в том числе wikilinks и тегов.
- Автосохранение с debounce ~800 мс, индикатор состояния (Saved / Saving / Offline).
- Конфликт версий: optimistic locking по полю `version`. При конфликте — диалог: оставить мою версию / загрузить серверную / показать diff.
- Автодополнение: после `[[` — поиск заметок по названию и aliases; после `#` — существующие теги.
- Вставка/перетаскивание файлов в редактор → загрузка → вставка `![[filename]]`.
- На экранах < 768 px split недоступен: переключатель Edit / Preview.
- Правая панель (сворачиваемая): **Backlinks**, **Linked tasks**, **Outline** (заголовки).

### 6.3 Превью (рендер markdown)
- GFM: таблицы, чекбоксы (только отображение), зачёркивание, автоссылки.
- Подсветка кода (shiki), темы синхронизированы с темой приложения.
- Wikilinks: `[[Note]]`, `[[Note|alias]]`, `[[Note#Heading]]`, `[[folder/Note]]`. Клик — переход. Ссылка на несуществующую заметку отображается отдельным стилем; клик создаёт заметку.
- Embeds: `![[image.png]]` — изображение, `![[file.pdf]]` — карточка файла со ссылкой.
- Callouts в стиле Obsidian (`> [!note]`) — желательно.
- Весь HTML санитизируется.

### 6.4 Теги
- Источники: inline `#tag`, вложенные `#parent/child`, поле `tags` во frontmatter.
- Панель тегов в сайдбаре: дерево с количеством заметок, клик — фильтр.
- Теги парсятся на бэкенде при сохранении и хранятся в отдельных таблицах.

### 6.5 Связи
- При каждом сохранении бэкенд парсит wikilinks и обновляет таблицу `note_links` (включая «висячие» ссылки на ещё не созданные заметки — чтобы при создании они резолвились).
- Резолв `[[Name]]`: поиск по названию и aliases среди всех заметок пользователя. Если совпадений несколько — используется точный путь `[[folder/Name]]`, а редактор подсвечивает неоднозначную ссылку предупреждением.
- **Backlinks:** список заметок, ссылающихся на текущую, с фрагментом контекста.
- **Переименование/перемещение заметки** предлагает автоматически обновить все ссылки на неё (диалог с количеством затронутых заметок).

### 6.6 Граф
- **Global graph** — отдельная страница: все заметки и связи.
- **Local graph** — в правой панели заметки, глубина 1–2 (переключатель).
- Фильтры: по папке, по тегу, скрыть «сиротские» заметки, показать/скрыть висячие ссылки, показать задачи как узлы (переключатель).
- Цвет узлов — по папке или тегу (настраивается), размер — по количеству связей.
- Клик по узлу — открыть заметку, hover — подсветка соседей, зум и панорамирование.
- Должен плавно работать на 2000 узлах (canvas/WebGL, не SVG).

### 6.7 Поиск
- **Quick switcher** (`Ctrl/Cmd+K`): нечёткий поиск по названиям заметок, задачам и командам.
- **Полнотекстовый поиск** (`Ctrl/Cmd+Shift+F`): PostgreSQL FTS, подсветка совпадений во фрагментах, фильтры `tag:`, `path:`, `in:tasks`, `in:notes`.
- Конфигурация FTS должна корректно работать с русским и английским текстом в заметках (например, отдельные `tsvector` для `russian` и `english` или `simple` + `pg_trgm` — на усмотрение агента, записать в DECISIONS).

### 6.8 Вложения
- Загрузка через drag & drop, вставку из буфера и кнопку.
- Лимит размера — `MAX_UPLOAD_MB` (по умолчанию 25). Проверка MIME по содержимому, а не по расширению.
- Хранение в docker volume, путь `/data/attachments/<user_id>/...`. Отдача только через авторизованный эндпоинт с проверкой владельца.
- Страница/панель вложений: список, где используются, удаление неиспользуемых.

### 6.9 Импорт и экспорт
- **Экспорт всего vault** в `.zip`: структура папок, `.md` файлы с frontmatter, вложения в папке `attachments/`. Архив должен открываться в Obsidian без правок.
- **Экспорт одной заметки** в `.md`.
- **Импорт Obsidian vault** из `.zip`: папки, заметки, frontmatter, теги, ссылки, вложения. Каталог `.obsidian/` игнорируется. Импорт выполняется в фоне, по завершении — отчёт (сколько импортировано, ошибки, конфликты имён).

## 7. Модуль Tasks

### 7.1 Сущность задачи
| Поле | Описание |
|---|---|
| `title` | обязательное |
| `description` | markdown, опционально |
| `list_id` | список/проект, по умолчанию Inbox |
| `priority` | none / low / medium / high |
| `due_date` | опционально |
| `due_time` | опционально, только если есть `due_date` |
| `is_recurring` + `rrule` | см. 7.4 |
| `parent_id` | подзадача (один уровень вложенности) |
| `status` | open / done, `completed_at` |
| `reminders_enabled` | по умолчанию `true` |
| связи | с заметками (7.5) |

### 7.2 Списки (проекты)
- **Inbox** создаётся автоматически, удалить нельзя.
- Пользовательские списки: название, цвет (из ограниченной палитры дизайн-системы), иконка, порядок (drag & drop), архивирование.
- При удалении списка — выбор: удалить задачи или перенести в Inbox.

### 7.3 Подзадачи и приоритеты
- Подзадачи создаются внутри задачи, прогресс отображается как `2/5`.
- Выполнение родителя с незавершёнными подзадачами — диалог: завершить все / отмена.
- Приоритет отображается приглушённым цветовым маркером, сортировка и фильтр по приоритету.

### 7.4 Повторяющиеся задачи
- Для повторяющейся задачи **обязательны дата и время** первого вхождения.
- Варианты: каждый день; каждую неделю (выбор дней недели); каждый месяц (число или «последний день»); каждый год; каждые N дней/недель/месяцев; кастомный.
- Окончание: никогда / до даты / после N повторений.
- Хранение — строка RRULE (RFC 5545) + `dtstart` в локальном времени пользователя + его часовой пояс.
- **Выполнение** вхождения: запись в `task_completions` (история), `due` сдвигается на следующее вхождение, задача остаётся открытой. Если вхождений больше нет — задача закрывается.
- **Skip this occurrence** — сдвиг без записи о выполнении.
- В календаре будущие вхождения отображаются как виртуальные (вычисляются на лету, не хранятся в БД).

### 7.5 Связь задач и заметок
- В задаче — блок **Linked notes**: добавить через поиск, удалить, клик открывает заметку.
- В заметке — панель **Linked tasks**: список связанных задач с чекбоксами выполнения и кнопка **New task from this note** (создаёт задачу, уже связанную с заметкой). Желательно: пункт контекстного меню «Create task from selection».
- Связь двусторонняя, хранится в одной таблице.
- Markdown-чекбоксы `- [ ]` в заметках задачами **не являются**.

### 7.6 Виды
- **List** — задачи выбранного списка; группировка (по дате / приоритету / без группировки), сортировка, фильтры, переключатель Show completed.
- **Today** — просроченные (отдельной группой сверху) + задачи на сегодня.
- **Upcoming** — следующие 7 дней по дням, далее группа Later.
- **Calendar** — вид «месяц» и «неделя»; задачи без времени — в all-day зоне; drag & drop меняет дату/время; клик по дню — быстрое создание задачи. На мобильных — вид «неделя» или агенда.

### 7.7 Quick add
- Поле быстрого добавления в каждом виде (хоткей `Q` или `Ctrl/Cmd+N` в разделе Tasks).
- Разбор естественного языка (английский): `Call mom tomorrow 18:00 !high #Personal` → дата, время, приоритет (`!low` / `!medium` / `!high`), список (`#ListName`). Повторы: `every monday 9am`.
- Распознанные части подсвечиваются прямо в поле ввода до подтверждения.

## 8. Напоминания

### 8.1 Настройки пользователя
- `timezone` — IANA-зона (по умолчанию из браузера при регистрации).
- `daily_reminder_time` — время «напоминаний за день», по умолчанию `09:00`, меняется в профиле.
- `notifications_enabled` — глобальный переключатель.

### 8.2 Правила (строго)

**Неповторяющаяся задача:**

| Состояние задачи | Какие напоминания |
|---|---|
| нет даты | никаких |
| есть дата, нет времени | одно: **за день** — в `(due_date − 1 день)` в `daily_reminder_time` |
| есть дата и время | два: **за день** — в `(due_date − 1 день)` в `daily_reminder_time`; **за час** — в `due_datetime − 1 час` |

**Повторяющаяся задача:** одно напоминание **ровно в момент каждого вхождения** (дата + время вхождения). Других напоминаний нет.

**Общие правила:**
- Если момент напоминания уже в прошлом на момент создания/изменения задачи — это напоминание **не отправляется** (без «догоняющих» сообщений). Решение вынести в константу, чтобы его было легко поменять.
- Выполнение, удаление задачи или выключение `reminders_enabled` отменяет её запланированные напоминания.
- Изменение даты, времени, правила повтора, часового пояса или `daily_reminder_time` пересчитывает все незавершённые напоминания затронутых задач.
- Подзадачи с датой получают напоминания по тем же правилам.

### 8.3 Содержимое сообщения
- Тип напоминания (`Tomorrow:` / `In 1 hour:` / `Now:`), название задачи, список, срок, приоритет.
- Inline-кнопка **Open** — ссылка на задачу в веб-приложении (`PUBLIC_URL`).

### 8.4 Реализация
- Таблица `scheduled_reminders`: `task_id`, `occurrence_at`, `remind_at` (UTC), `kind` (`day_before` / `hour_before` / `occurrence`), `status` (`pending` / `sent` / `cancelled` / `failed`), `attempts`, `last_error`. Уникальный индекс `(task_id, occurrence_at, kind)` — идемпотентность.
- Все моменты вычисляются из локального времени пользователя через `zoneinfo` и хранятся в UTC (корректная работа при переходах на летнее/зимнее время).
- Для повторяющихся задач в таблице всегда хранится **только следующее** вхождение. После отправки или выполнения/пропуска планируется следующее.
- Процесс `worker`: цикл каждые 30 с, выбирает `pending` с `remind_at <= now()` через `SELECT ... FOR UPDATE SKIP LOCKED`, отправляет через Telegram Bot API, обновляет статус.
- Ошибки отправки: до 3 повторов с экспоненциальной задержкой, затем `failed`. Если пользователь заблокировал бота — флаг `telegram_blocked` у пользователя и баннер в веб-интерфейсе с просьбой разблокировать бота.
- Воркер после простоя (например, сервер был выключен) отправляет напоминания, просроченные **не более чем на 15 минут**, остальные помечает `cancelled`.
- **Обязательные тесты** (с заморозкой времени): все строки таблицы из 8.2, прошедшие моменты, смена часового пояса, DST, выполнение и пропуск повторяющейся задачи, изменение даты, отсутствие дублей.

## 9. Telegram-бот

- aiogram 3, режим **long polling** по умолчанию (не нужен публичный домен). Webhook — опционально через `BOT_MODE=webhook`.
- Все тексты бота на английском.
- Сообщения от непривязанных пользователей: короткий ответ «This bot works only with a linked account» + ссылка на `PUBLIC_URL`.

### Команды
| Команда | Действие |
|---|---|
| `/start link_<token>` | привязка аккаунта (5.2) |
| `/start login_<token>` | подтверждение входа (5.3) |
| `/new <text>` или просто текст | создание задачи |
| `/lists` | показать списки (для справки) |
| `/help` | справка по синтаксису |
| `/unlink` | отвязать Telegram (с подтверждением) |

### Создание задачи из бота
- Любое текстовое сообщение без команды = новая задача.
- Парсинг тем же синтаксисом, что quick add (7.7): дата, время, `!priority`, `#List`, повторы `every ...`. Для дат желательно поддержать и русский ввод («завтра в 18:00»).
- Бот сразу создаёт задачу и отвечает сводкой (название, список, срок, приоритет, повтор) с кнопками **Change list**, **Undo**.
- Для повторяющейся задачи без времени бот спрашивает время кнопками/сообщением, так как время обязательно (7.4).
- Логику разбора текста вынести в общий модуль бэкенда, используемый и API quick add (если разбор делается на сервере), и ботом.

## 10. Дизайн

### 10.1 Принципы
Спокойный, тёплый, неперегруженный интерфейс, в котором главное — контент. Ощущение аккуратного инструмента для работы, а не маркетингового лендинга. Много воздуха, чёткая типографика, минимум декора.

### 10.2 Чего НЕ делать (признаки «ИИ-шного» дизайна)
- Фиолетово-синие градиенты, неоновое свечение, glassmorphism, blur-фоны.
- Иконки «искорок», эмодзи в заголовках и кнопках.
- Дефолтный вид shadcn/ui без переработки.
- Карточки с крупными тенями и `rounded-2xl` на всём подряд.
- Inter как единственный шрифт везде.
- Сгенерированные иллюстрации в пустых состояниях.
- Бейджи и цветные плашки на каждом элементе.

### 10.3 Цвета (стартовые токены, можно уточнить)
Тёплые нейтральные тона + **один** приглушённый акцент, используемый дозированно (активный пункт, основная кнопка, фокус).

| Токен | Light | Dark |
|---|---|---|
| `--bg` | `#FAF9F5` | `#1C1B19` |
| `--surface` | `#F3F1EA` | `#252421` |
| `--surface-raised` | `#FFFFFF` | `#2C2B28` |
| `--border` | `#E5E2D9` | `#363430` |
| `--text` | `#1F1E1B` | `#ECEAE3` |
| `--text-muted` | `#6B6860` | `#9C998F` |
| `--accent` | `#C2663F` | `#D9805A` |
| `--danger` | `#B5483A` | `#D0685A` |

- Цвета приоритетов и списков — приглушённые, из фиксированной палитры, контраст не ниже WCAG AA.
- Все цвета только через CSS-переменные.

### 10.4 Типографика
- Заголовки и названия заметок — serif (например, Source Serif 4, Newsreader или Literata).
- Интерфейс — humanist sans (например, IBM Plex Sans или Source Sans 3).
- Редактор и код — mono (JetBrains Mono или IBM Plex Mono).
- Ширина текста в превью — не более ~72ch, межстрочный интервал 1.6–1.7.
- Выбор конкретных шрифтов — на усмотрение агента, в DECISIONS.

### 10.5 Форма и движение
- Сетка отступов 4 px, щедрые поля.
- Радиусы небольшие (4–8 px). Разделение блоков — тонкими границами и фоном, тени только у поповеров, меню и модалок.
- Анимации 120–180 мс, только функциональные (открытие панелей, drag & drop). Учитывать `prefers-reduced-motion`.

### 10.6 Раскладка
- Слева: сворачиваемый сайдбар — переключатель **Notes / Tasks**, дерево папок или списки, теги, ссылки на Graph, Search, Trash, Settings.
- Центр: рабочая область.
- Справа: сворачиваемая контекстная панель (Backlinks, Linked tasks, Outline, Local graph).
- Командная палитра `Ctrl/Cmd+K` доступна везде. Страница `Keyboard shortcuts` (`?`).

### 10.7 Темы
- Light / Dark / System, переключатель в сайдбаре и настройках, выбор сохраняется в профиле.
- Без «вспышки» неправильной темы при загрузке (inline-скрипт в `index.html`).
- Подсветка кода и граф учитывают текущую тему.

### 10.8 Адаптив
- Корректная работа от 360 px.
- < 768 px: сайдбар → выезжающая панель, правая панель → нижний лист (bottom sheet), редактор в режиме Edit/Preview, календарь → неделя/агенда.
- Тач-зоны не меньше 44 px.

### 10.9 Качество UI
- Полная навигация с клавиатуры, видимые focus-состояния.
- Пустые состояния: одна короткая фраза + действие.
- Скелетоны вместо спиннеров там, где загрузка заметна.
- В dev-режиме страница `/styleguide` со всеми токенами и базовыми компонентами в обеих темах.

## 12. API

REST, префикс `/api/v1`, OpenAPI доступен по `/api/docs` (только в dev или для админа). Основные группы:

- `auth` — login, logout, refresh, telegram login start/status, invite accept, password reset, sessions
- `me` — профиль, настройки, telegram link start/status, unlink
- `admin` — invites, users
- `folders`, `notes` (CRUD, move, rename с обновлением ссылок, backlinks, local graph, export)
- `tags`, `graph`, `search`
- `attachments` (upload, download, list, delete)
- `import` (upload zip, статус задачи)
- `lists`, `tasks` (CRUD, complete, skip, subtasks, note links, views `today` / `upcoming` / `calendar?from&to`)
- `quick-add/parse` — разбор строки (если разбор на сервере)
- `health`

Ошибки — единый формат `{ "error": { "code", "message", "details" } }`. Пагинация — cursor-based для списков.

## 13. Безопасность, деплой, эксплуатация

### Безопасность
- Все пароли и токены (инвайты, refresh, link/login) хранятся только как хеши.
- Санитизация markdown-HTML, строгий CSP в nginx, заголовки `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`.
- Защита от path traversal при работе с вложениями и импортом zip (в том числе zip-bomb: лимит на распакованный размер и количество файлов).
- Логи без паролей, токенов и содержимого заметок.

### Docker Compose
- Сервисы: `db` (postgres:16), `api`, `worker`, `bot`, `web`.
- Volumes: `pgdata`, `attachments`.
- Healthchecks для всех сервисов, `api` применяет миграции Alembic при старте.
- Наружу публикуется только `web` (порт из `.env`, по умолчанию 8080).

### `.env.example` (минимум)
```
APP_NAME=Nook
PUBLIC_URL=http://localhost:8080
SECRET_KEY=
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_DB=
TELEGRAM_BOT_TOKEN=
TELEGRAM_BOT_USERNAME=
BOT_MODE=polling
ADMIN_USERNAME=
ADMIN_PASSWORD=
MAX_UPLOAD_MB=25
WEB_PORT=8080
```

### Эксплуатация
- Скрипт `deploy/backup.sh`: `pg_dump` + архив вложений с датой в имени; инструкция по восстановлению в README.
- Структурированные JSON-логи.
- README: требования, установка за 5 шагов, создание бота в BotFather, первый вход, обновление версии, бэкап/восстановление, пример HTTPS через Caddy.
